# Kiwoom-Intraday-Signal-Research

국내 주식 급등주를 대상으로 한 실시간 데이터 수집·초단기 신호 예측 및 오프라인 검증 프로젝트
진행 기간: 2026년 9월~11월 | 상태: 종료·아카이브 | 실거래: 없음
프로젝트의 결론: 키움증권 REST/WebSocket 기반 데이터 수집과 머신러닝 실험 환경을 구축했지만, 여러 오프라인 검증에서 거래비용을 차감한 후의 안정적인 수익성을 확인하지 못했다. 시스템은 데이터 수집·분석 단계(COLLECT)에서 종료했으며, 실전 주문을 실행하지 않았다.

공개 상태: 이 README는 공개 저장소용 초안이다. 코드·설정의 보안 검토와 재배포 가능 여부를 확인하기 전에는 실제 소스·데이터 공개를 완료한 것으로 간주하지 않는다.

1. 프로젝트 개요
출발점은 간단한 질문이었다. 변동성이 큰 급등주 가운데, 짧은 시간 안에 추가로 상승할 신호를 구분할 수 있을까? 초기에는 수익을 목표로 하는 초단타 자동매매 시스템을 구상했지만, 진행 과정에서 문제를 신호의 타당성, 예측의 재현성, 거래비용, 가격 경로의 검증으로 구체화했다.

당초 기준은 월간 수수료 포함 순수익률 약 +2%였다. 처음 검토한 거래당 +0.7~1.0% 목표와 120초 보유 가정은, 이후 +0.40~0.50% 목표 및 30/60/120초 보유 조건을 비교하는 방향으로 변경되었다. 목표 수익률은 연구 목표였으며 달성 성과가 아니다.
2. 시스템의 구성
키움 REST / WebSocket
        │
        ▼
실시간 종목 선정·시세/호가/체결 수집
        │
        ▼

        ▼
SQLite 주간 DB + Future Diagnostics + 운영 리포트
        │
        ├──► 주간·누적 학습용 데이터셋 생성
        │               │
        │               ▼
        │       Google Drive / Google Colab
        │               │
        │               ▼
        │       Multi-head 모델 학습·오프라인 분석
        │
        └──► 서버 추론/점수화 경로(적용 정합성은 실험별 확인 필요)

실주문 발주: 비활성화(COLLECT)
처음에는 Linux VPS에서 수집과 학습을 모두 처리하려 했으나, W38의 메모리 부족(OOM)·디스크 포화를 계기로 서버의 수집/전처리와 Colab의 학습/분석을 분리했다. Python, SQLite, PyTorch, Linux/systemd, Google Drive, Google Colab, rclone 등을 사용했다.
Multi-head 모델
상승 가능성(A), 급락 위험(B), 단기 상승 분출 가능성(C), 유동성·슬리피지 위험(D)을 분리해 평가하는 구조를 검토했다. 기록된 점수 구성의 기본 형태는 아래와 같다.
S_raw = wA·A − wB·B + wC·C − wD·D
입력 피처는 23개에서 최대 25개까지 확장하는 방향으로 개발되었지만, 실험 주차에 따라 23/24/25개 버전과 학습/서버 추론의 정합성 문제가 있었다. 따라서 이 저장소는 최종 모델의 일관된 예측 성능을 보증하지 않는다.

4. 검증에서 확인한 한계
- 마찰 비용: 여러 시뮬레이션은 왕복 거래 비용·스프레드·슬리피지를 합산한 약 0.25%의 비용 가정을 사용했다. 이 값은 모든 종목·시점의 실제 체결 비용이 아니라 모델링 가정이다.
- 스냅샷과 경로의 차이: 30초나 60초 뒤 가격이 상승해도, 그전에 손절선에 먼저 닿으면 거래 결과는 달라진다. 이를 확인하기 위해 MFE/MAE와 Target-First/Stop-First 분석을 시도했다.
- 시간대/신호별 이질성: 예시로 60초 기준 AFTER_10 C2 집단의 비용 차감 평균은 W41 -0.2022%(522건), W42 -0.2155%(821건)였다. 이는 특정 코호트·가정의 출력이지 실계좌 수익률이나 전체 전략 성적이 아니다.
- 학습 모델 적용 상태: research_final_signal_test_v1의 W41~W42 신호 3,257건에서 trained_model=0, model_source=RUNTIME_JSON_PRETRAIN_ONLY, 진입 승인 0건으로 기록되었다. 이것만으로 모든 모델 실험이 미적용되었다고 단정할 수는 없으나, 해당 진단 집단을 학습 모델의 실제 진입 성과로 해석해서는 안 된다.
- 백테스트 구현의 한계: 일부 초기 Colab 출력에서 점수 컬럼이 없을 때 기본 점수로 대체되어, 의도한 상위 점수 필터가 적용되지 않았을 가능성이 확인되었다. 결과를 재현 가능한 수익성 입증으로 취급하지 않는다.
5. 데이터와 재현 가능성
최근 W46 누적 매니페스트에 관해 확인·보고된 값은 36거래일, 1,366종목, 누적 정제 학습 샘플 1,255,662행이다(W37~W39 및 W41~W46, W40 제외). 수백만 건 단위의 주간 원본 신호 수, 주간 라벨 생성 수, 정제 학습 샘플 수는 서로 다른 지표이며 혼용하지 않는다.

원본 시세·호가·체결 데이터, 개인 운영 설정, 인증정보, 원본 DB 및 비공개 모델/실험 결과는 공개 저장소에 기본 포함하지 않는다. 따라서 저장소만으로 당시의 전체 데이터 수집·학습 결과를 재현할 수 있다고 주장하지 않는다. 공개 코드의 의존성과 샘플 데이터·테스트 가능 범위는 최종 보안 검토 이후에 확정한다.
6. 실제 구현과 미검증 사항
기록상 수행: 실시간 데이터 수집·저장, 주간 집계/압축, 오프라인 학습용 데이터 생성, 다중 출력 모델 코드·가중치 생성, 코호트/거래비용/가격 경로 진단, 백업 및 운영 자동화.

구현 또는 실효성 확인이 미완료: 유효한 순수익 전략, 라이브 주문/체결·계좌 대사, 부분체결·실슬리피지 관리, 모델 배포 경로 전체의 일관성, 계획했던 손실 함수 개선 후의 검증, 장기 시장 국면에 걸친 통계적 재현성.

시스템은 COLLECT 단계에서 종료되었으며 Shadow Trading·MOCK·LIVE 단계의 운영 실적을 주장하지 않는다.
7. 개발 방식과 AI 활용
이 프로젝트는 생성형 AI를 적극 활용한 협업 개발 프로젝트다. 사용자는 문제 정의, 목표 및 전략 변경 결정, 실험에 대한 질문, 통계·로그의 재확인, 인프라 운영, 최종 중단 결정을 수행했다. 생성형 AI는 상당 부분의 코드 작성·설계 대안·분석 스크립트 및 해석 초안에 관여했다.

따라서 이 저장소를 개발자가 모든 Python/ML 코드를 독립적으로 작성했거나, 독자적으로 학습 알고리즘을 고안한 프로젝트로 설명하지 않는다. AI가 작성한 코드 역시 검토 과정에서 오류와 불일치가 발견되었으며, 그 자체로 정당성이 보장되지 않는다.
8. 종료와 공개 원칙
2026년 11월 프로젝트를 중단하고, 원본 데이터·코드·실험 기록을 비공개로 보존하기로 결정했다. 공개하는 내용은 재현에 필요한 권한이 명확한 코드와 기술적 의사결정·실패 분석에 한정할 예정이다. 공개 전 반드시 자격증명, 개인 계정 정보, IP/호스트 정보, 로그·DB의 민감정보, 데이터 라이선스, 대용량 파일 여부를 검토한다.
