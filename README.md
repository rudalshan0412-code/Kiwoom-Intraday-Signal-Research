# Kiwoom Intraday Signal Research

### 급등주 초단기 가격 예측 및 데이터 수집 프로젝트

2026년 9월 – 11월 · Python / PyTorch / SQLite / Kiwoom API · 개발 종료

급등하는 국내 주식에서 추가 상승을 예측할 수 있을지 알아보기 위해 시작한 개인 프로젝트입니다. 키움증권 API를 이용한 실시간 데이터 수집 환경을 구축하고, 수집한 데이터를 바탕으로 초단기 신호와 머신러닝 모델을 검증했습니다.

처음에는 자동매매까지 구현하는 것이 목표였지만, 여러 실험에서 거래비용을 반영한 안정적인 수익성을 확인하지 못했습니다. 프로젝트는 데이터 수집과 오프라인 검증 단계에서 종료했으며, **실제 주문이나 실거래는 진행하지 않았습니다.**

## 프로젝트를 시작한 이유

처음 세운 가설은 단순했습니다.

> 변동성이 큰 급등주에서도 추가 상승이 이어지는 구간을 구분할 수 있다면, 짧은 시간의 가격 움직임을 활용할 수 있지 않을까?

초기 목표는 월 2%의 비용 차감 순수익이었습니다. 다만 개발을 진행할수록 단순히 상승을 예측하는 것보다 호가 스프레드, 체결 가능성, 손절에 먼저 도달하는 가격 경로를 함께 고려하는 것이 중요하다는 점을 확인했습니다.

프로젝트의 중심도 자동매매 구현에서 **예측 신호의 타당성과 실제 거래 가능성을 검증하는 작업**으로 옮겨갔습니다.

## 구현한 시스템

```text
Kiwoom REST API / WebSocket
              │
              ▼
       실시간 시세·호가·체결 수집
              │
              ▼
          신호 및 피처 생성
              │
              ▼
       SQLite 주간 데이터베이스
              │
      ┌───────┴────────┐
      ▼                ▼
  진단·운영 기록      주간·누적 데이터셋
                       │
                       ▼
                Google Drive / Colab
                       │
                       ▼
                모델 학습·백테스트
```

주요 구성은 다음과 같습니다.

- **데이터 수집:** 국내 주식의 실시간 시세, 호가, 체결 정보와 신호 기록
- **데이터 처리:** 주간 SQLite DB, 미래 가격 진단, 학습용 데이터셋 및 운영 리포트 생성
- **모델 실험:** 상승 가능성, 하락 위험, 단기 상승 분출, 유동성 위험을 분리한 Multi-head 모델
- **전략 검증:** 시간대·신호 유형·보유시간별 비교, 거래비용과 목표가·손절가 선도달 분석
- **운영 자동화:** Linux 서비스 운영, 주간 작업, 백업 및 장애 복구

처음에는 저사양 Linux 서버에서 수집과 학습을 함께 수행했습니다. 데이터가 증가하면서 메모리 부족과 디스크 포화가 발생해, 서버는 수집·전처리를 담당하고 Google Colab에서 학습과 분석을 수행하는 구조로 변경했습니다.

## 결과와 한계

### 1. 거래비용을 반영하면 결과가 달라졌습니다

일부 실험에서는 가격 상승 가능성이 관측됐지만, 약 0.25%의 거래 마찰 비용을 가정하면 평균 수익률이 음수인 조건이 많았습니다. 이는 실제 체결 데이터를 통해 측정한 고정 비용이 아니라 백테스트에 사용한 가정입니다.

예를 들어 60초 보유를 가정한 `AFTER_10 / C2` 코호트의 비용 차감 평균 결과는 다음과 같았습니다.

| 데이터 | 신호 수 | 평균 수익률 |
| --- | ---: | ---: |
| W41 | 522 | -0.2022% |
| W42 | 821 | -0.2155% |

위 수치는 특정 조건에서 나온 오프라인 분석 결과이며, 전체 전략의 수익률이나 실계좌 성과가 아닙니다.

### 2. 예측 점수의 출처도 확인해야 했습니다

W41·W42 신호 정의 점검 자료 3,257건에서는 모두 `trained_model=0`으로 기록됐습니다. 학습 모델의 실제 추론 결과와 기본 점수·대체 경로를 구분하지 않으면, 점수 기반 분석을 잘못 해석할 수 있다는 문제를 확인했습니다.

해당 자료에 한정된 결과이며, 모든 주차의 학습 및 추론이 동일한 상태였다는 의미는 아닙니다.

### 3. 가격 변화와 거래 결과는 같지 않았습니다

30초 뒤 가격이 상승했더라도 그 전에 손절선에 먼저 닿았다면 실제 거래 가정에서는 손실일 수 있습니다. 이에 따라 단순한 미래 시점 가격 비교에서 목표가·손절가에 먼저 도달하는 순서를 고려한 검증으로 분석 범위를 넓혔습니다.

### 4. 실거래 수익성은 입증하지 못했습니다

모델 코드와 데이터 수집·분석 파이프라인은 구축했지만, 안정적으로 비용을 넘어서는 전략과 실시간 체결 성능은 검증하지 못했습니다. 실주문 기능의 운영 결과도 없습니다.

## 생성형 AI 활용

이 프로젝트는 생성형 AI의 도움을 받아 개발했습니다. 코드 구현뿐 아니라 모델 구조와 실험 방법, 분석 스크립트 작성에도 AI의 기여가 컸습니다.

직접 수행한 역할은 목표와 실험 질문을 정하고, 분석 결과와 로그를 확인하며, AI의 제안에 오류나 논리적 문제가 없는지 검토하고, 개발 방향과 종료 여부를 결정하는 것이었습니다. 코드 전체를 독립적으로 구현한 프로젝트로 소개하지는 않습니다.

## 공개 범위

이 저장소는 수익성이 입증된 자동매매 프로그램을 배포하기보다, 데이터 수집 시스템을 만들고 검증해 온 과정을 기록하기 위한 공간입니다.

원본 시장 데이터, DB, 인증정보, 개인 운영 설정 등은 공개하지 않습니다. 코드의 공개 범위와 재현 가능한 실행 환경은 보안 및 데이터 재배포 권한을 검토한 뒤 결정합니다. 따라서 공개된 문서나 코드만으로 당시의 전체 실험을 그대로 재현할 수 있다고 보장하지 않습니다.

> **참고:** 투자 권유나 수익 보장을 위한 프로젝트가 아닙니다.
